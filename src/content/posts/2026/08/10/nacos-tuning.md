> Nacos 的调优重点是**容量与稳定性**：能承载多少服务实例、多少配置变更、客户端长连接（gRPC）与推送如何并发。单机 Derby 模式只配测试；生产调优的第一动作就是**外接 MySQL 并组成 3 节点集群**。部署安装见《大数据与中间件组件部署总览》。

## 核心参数与调优理解

| 参数 | 默认值 | 调优理解 |
| ---- | ---- | ---- |
| JVM 堆（`-Xms/-Xmx`） | 1G | 实例数与配置量决定；几万实例规模 4~8G 足够，**堆大不等于能扛更多连接** |
| `nacos.naming.empty-service.auto-clean` | false | 自动清理空服务，频繁上下线的环境开启 |
| `nacos.naming.distro.task.*` | 默认 | 集群数据同步任务线程，节点多时按默认即可，别乱调 |
| gRPC 端口 | 9848/9849 | 客户端与集群间通信，**防火墙漏放是连接事故主因** |
| 客户端心跳/重连 | gRPC 长连接 | 2.x 客户端基于 gRPC 长连接，**客户端版本尽量对齐服务端** |
| `nacos.core.auth.enabled` | false | **生产必须开启**，未开启的 Nacos 可被任意读写配置 |
| 保护阈值（Protect Threshold） | 0 | 服务下健康实例比例低于阈值时，将不健康实例也参与返回，防雪崩 |

:::note
**2.x 与 1.x 的容量差异**：1.x 客户端用 HTTP 轮询（30s 长轮询），2.x 用 gRPC 长连接+服务端推送。2.x 单节点可支撑的服务实例数远高于 1.x，但长连接数量受文件句柄与线程限制，`ulimit -n` 要放行。
:::


## 三档规格推荐参数

| 参数 | 8C16G（中小规模） | 32C256G（大规模） | 64C512G（超大规模） |
| ---- | ---- | ---- | ---- |
| 集群节点 | 3（独立部署） | 3~5 | 5 |
| JVM 堆 | 4G | 8G | 16G |
| 元数据库 | MySQL 独立实例 | MySQL 主从 | MySQL 主从 + 独立实例 |
| 最大服务数（规划值） | 1 万内 | 5 万内 | 10 万+ |
| 单机连接上限规划 | 5 万内 | 10 万内 | 20 万内 |
| `nacos.naming.empty-service.auto-clean` | true | true | true |

:::warning
Nacos 是**控制面组件，不承担业务流量**。32C256G/64C512G 规格的机器跑 Nacos 是浪费——按上表 8C16G/16C32G 独立部署即可，大规格列的差异体现在**集群节点数、MySQL 冗余与连接规划**上，而不是单机堆料。
:::


## 集群规模优化（几十~上百节点）

- **集群节点数：3 起步，5 封顶**：Nacos 用 Raft（JRaft）选主，节点越多写入越慢；100 节点应用集群的接入方是"几百个应用 + 几千实例"，Nacos 3~5 节点完全够
- **命名空间/分组规划**：生产按环境（dev/test/prod）与业务线划分 namespace，配置与服务的可见范围收敛，避免"一锅烩"
- **配置变更节流**：配置批量推送会打满 gRPC 推送线程，变更走"分批次发布"，高峰期不批量改配置
- **服务健康检查**：客户端心跳（gRPC）与服务端主动探测并存；临时实例（ephemeral）数量大时，关注服务端线程与内存
- **客户端侧**：服务发现不阻塞主流程（fail-fast + 本地缓存），注册中心抖动不影响业务
- **与 K8S 结合**：云原生环境用 DNS 或 K8s 服务发现兜底，Nacos 作为配置中心为主

## 容灾与备份

| 层级 | 手段 | 说明 |
| ---- | ---- | ---- |
| 集群内 | 3~5 节点 Raft | 半数以上存活即可用，节点故障自动选主 |
| 数据 | MySQL 主从 | 元数据存 MySQL，主从保证库级可用；`mysqldump` 每日全量 |
| 配置 | 配置导出 | 控制台批量导出全部配置，版本管理与灾备 |
| 客户端 | 本地缓存兜底 | 客户端启动拉取并缓存配置，Nacos 全挂服务仍可用旧配置运行 |

## 调优常见问题

- **服务注册成功但客户端发现不到**：检查 9848 gRPC 端口连通（`telnet <ip> 9848`）、客户端版本与服务端大版本是否一致
- **配置变更未生效/推送失败**：客户端 gRPC 断连重连中；看服务端 `push` 相关日志，检查 namespace 是否匹配
- **控制台/API 401**：`nacos.core.auth.enabled` 开启后未配 token（`nacos.core.auth.plugin.nacos.token.secret.key`），生产必须显式配置密钥
- **集群脑裂/节点互相踢**：节点间 9849 不通、或 clock 偏差；确认集群网络与时钟同步
- **启动报数据库连接失败**：MySQL 未就绪或 `db.url.0` 配置错误，检查 `application.properties`

## 调优检查清单

1. 生产必做：3 节点集群 + MySQL + 认证开启
2. 9848/9849 端口放行，客户端版本对齐
3. 命名空间与分组规范，配置版本管理
4. 堆 4~8G（按实例数），不盲目堆料
5. MySQL 主从 + 每日备份 + 配置导出
6. 变更节流与监控（控制台节点状态、gRPC 连接数）
