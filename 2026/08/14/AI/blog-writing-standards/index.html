博客写作与维护规范（项目常规操作）

本文最后更新于 2026-09-02T00:53:38+08:00

2026-08-13 发布的两篇求职分析文章在复盘时暴露了三类问题：时间先后不一致、内容重复、语句不通顺。修订完成后，我把这类问题固化为本博客项目的常规操作要求，作为每篇文章发布前的自检清单。

涉及文章：

  • DeepSeek「Agent Infra 研发工程师」岗位分析与自我匹配评估
  • DeepSeek 研发岗位全量扫描与自我匹配评估

规范一：时间与引用一致

  1. 同一批文章必须明确先后：发布时间戳按写作顺序递增，”上一篇/下一篇”的引用必须与实际时间顺序一致。同一时刻发布多篇是禁止的。
  2. 不得引用不存在的文章：只在聊天或草稿里存在的内容，不能写成”上一篇博客的结论”；改为”此前评估的结论”并注明未单独成文。
  3. 跨篇引用优先用固定链接：引用具体文章时使用 permalink；只有顺序已确定时，才允许使用”上篇/下篇”。
  4. 文章修订后必须更新 front matter 的 lastMod。

规范二：内容去重

  1. 总表与详解分工：总表只给结论和一句话判断，细节全部放详解；详解不复述总表。
  2. 跨篇去重：同一个事实（如”opencode 会话库 376MB”）全站只在一篇详述，其余文章用交叉引用代替复述。
  3. 通用计划与岗位专属计划分层：岗位篇只写该岗位的动作；汇总篇写全局计划，并注明与岗位篇的覆盖关系，避免两处各写一份。
  4. 被引用的章节名保持准确（如”独特的视角优势”），引用时不得张冠李戴。

规范三：语句通顺

  1. 禁止电报式短语（如”0 → 1 有”），每个条目写成完整句子。
  2. 引文内不夹带批注符号（如 ✅/❌ 不得出现在引号内的 JD 原文中），批注放在引文之外。
  3. 名词不直接当动词、口语不与书面语混用（如”打卡是证据”应写作”打卡记录是证据”）。
  4. 数据表述清晰（如”已 4 年+”应写作”已有 4 年多经验”）。
  5. 发布前必须通读一遍全文，逐条对照上述清单。

规范四：发布流程（附）

  1. 统一使用 npm run publish（等价于 hexo generate && hexo deploy --generate=false）。
  2. 禁止在 hexo clean 之后直接 hexo deploy——曾因此导致首页与归档页漏生成、线上 404。若必须 clean，则 clean 后先单独 generate 并核对产物，再 deploy --generate=false。
  3. 发布后等待 GitHub Pages 构建完成（约 1~2 分钟），并抽查首页、归档页与新增文章页是否 200。

规范五：分类使用

  1. summary 分类只放个人总结与个人思考，不放技术文档、岗位分析与规范类内容。
  2. 与 AI 相关的内容统一放 AI 分类（2026-08-14 起执行）。
  3. 新增分类前，先确认没有可复用的既有分类。
  4. 调整分类不影响文章 permalink，但调整后需重新生成并核对分类页与归档页。

规范六：文章归档默认值

  1. 默认不归档：新文章 front matter 不设置 archive: true，除非明确声明需要归档。归档字段的作用是让文章从首页时间线隐藏（仍可通过归档页、分类与标签访问），不是”已发布/未发布”的标记。
  2. 存量归档不动：2026-08-15 之前已带 archive: true 的文章保持原样，不因本规范回改。
  3. 归档与否不影响文章 permalink，但调整后需重新生成并核对首页与归档页。

本次修订记录（2026-08-14）

对上述两篇文章应用本规范后的具体修改：

时间与引用一致性

  • 第一篇发布时间改为 2026-08-13 21:30，第二篇保持 23:59，两篇的”下一篇/上一篇”引用与实际顺序一致。
  • 第一篇引言中”上一篇对「Agent Harness 研发/工程方向」的分析结论”改为”此前做过一轮评估”——该结论未单独成文，不再虚指为一篇博客。
  • 第二篇中”上篇已分析”的 Agent Harness 表述改为”此前评估的结论，未单独成文”。
  • 两篇 lastMod 更新为 2026-08-14。

内容去重

  • 第二篇删除”结论先行”里与总排序表重复的三个百分比描述，只保留方向提示。
  • 第二篇删除”第二梯队简评”中 Agent Infra 条目（与总排序表及上篇重复），改为”上篇已逐条分析，此处不重复”。
  • opencode 376MB 的事实只在第一篇详述，第二篇两处引用改为交叉引用。
  • 补课优先级中的可观测性与 Rust 两条与第一篇”行动计划”合并，第二篇只保留新增的 Python 数据栈条目并注明覆盖关系。
  • 第一篇行动计划第 5 条补充指向第二篇汇总的引导句。

语句通顺

  • 加分项八条由电报式短语改为完整句（如”0 → 1 有”→”0 → 1 的完整经历有”）。
  • JD 引文内的 ✅/❌ 批注移出引号（”Redis/Kafka ✅”→”对应 Redis/Kafka ✅”）。
  • “91 天 LeetCode 打卡是现成的证据”→”打卡记录是现成的证据”。
  • “到 2026 年已 4 年+（Go/Java）”→”已有 4 年多后端经验（Go/Java）”。
  • “经历’极端的运维抗压工作’”→”有过长期高强度驻场运维的经历”。
  • “投递时必须注明’后端专项、主场 Go’”→”‘后端专项（主场：Go）’”。

分类调整

  • 新建 AI 分类；两篇岗位分析文章、本文与「AI Agent 知识概念总结」从 summary 迁至 AI；置顶的「未来学习计划」由未分类归入 AI。
  • 依据见规范五：summary 只保留个人总结与个人思考。

本次修订记录（2026-08-15）

新增规范六：文章归档默认值

  • 规则来源：WSL2 恢复与 Docker 落地文章修订时，明确”默认不归档、除非显式声明”。
  • 新增”规范六：文章归档默认值”：新文章默认不设置 archive: true，存量已归档文章不回改。
  • 本规范文档自身带 archive: true，属于存量归档文章，按规范六第 2 条保持原样。

本规范本身同样适用以上所有条款；后续每篇文章发布前按规范一至四自检。
